# Public experiments

Write PR titles and descriptions in plain, everyday language. Explain what was
tried, what happened, and which checks passed. Keep technical details in linked
code or benchmark documents when they would make the PR harder to understand.
State failed results clearly and keep them in the evidence.

Public descriptions and new benchmark files must omit personal machine names,
user names, real directory paths, network addresses, credentials, private audio,
transcripts, token IDs, and raw model values. Use neutral path and recording
labels. Anonymous hardware specifications, software versions, timings, counts,
quality results, and integrity hashes may be recorded for reproducibility.

Keep every declared benchmark case and repeat, including slow or failed runs.
Explain how the overall speedup is calculated. Keep complete-input timing,
kernel timing, and throughput claims clear about their measured scope.
